# План: Автоматический запуск роботов с настраиваемым количеством через ENV (Вариант Б)

## 1. Цель
Перевести запуск симуляции на конфиг-ориентированный подход. Управление количеством активных роботов выносится в переменную окружения `NUM_ROBOTS`. Роботы спавнятся на всех точках парковки `parking` в конфиге карты; не превышающие лимит показываются как `inactive`/`dead`. Перегенерация SDF при смене `NUM_ROBOTS` не требуется.

## 2. Принятые решения
- Источник правды — секция `parking:` в `config_nodes_edges/<MAP>.yaml`. Если секция `robots` отсутствует или пуста — роботы выводятся из парковок.
- Парковки сортируются по имени (`P1, P2, ...`) для предсказуемой нумерации `robot_1..robot_N`.
- `NUM_ROBOTS` ограничивает количество активных роботов; если больше парковок — обрезается до их числа.
- Все роботы (включая неактивные) спавнятся в Gazebo в SDF. Только активные получают драйвер и мост.
- Неактивные роботы отображаются в веб-таблице со статусом `inactive`/`dead`, без кнопок управления.
- Команда «пойди домой» (`go_home`) без указания точки — робот едет на свою фиксированную парковку `home_parking`.
- Перенос моста `ros_gz_bridge` в контейнер `ros` (вместе с драйверами) — единый bringup. В `gazebo` остаётся только `gz sim`.

## 4. Порядок внедрения

1. Создать пакет `warehouse_bringup` (файлы выше).
2. Написать `launch/warehouse_bringup.launch.py` с `OpaqueFunction` — чтение YAML, сортировка парковок, фильтр `NUM_ROBOTS`, генерация `ExecuteProcess` для драйверов активных роботов, `TimerAction` + `parameter_bridge` под активных.
3. Добавить `pyyaml` в `docker/Dockerfile.ros`.
4. Правки `docker-compose.yml`: `ros` запускает bringup; `gazebo` только `gz sim`; `NUM_ROBOTS` во все сервисы.
5. Правки `.env`: `NUM_ROBOTS`.
6. Правки `gen_world.py`: спавн моделей под все парковки.
7. Правки `orchestrator/main.py`: автогенерация из parking, home_parking, эндпоинт `go_home`, исключение неактивных из логики.
8. Правки веб-интерфейса: кнопка домой, отображение inactive.
9. `colcon build` в `ros_ws`.
10. Тест `MAP=simple docker compose up --build` без `docker compose exec`.
11. Тест `MAP=stress NUM_ROBOTS=3` — только 3 активных, остальные inactive.
12. Тест `NUM_ROBOTS=10` (больше парковок) — обрезается до числа парковок.

## 5. Критерии приёмки
- `docker compose up --build` поднимает всех роботов без `docker compose exec`.
- При `MAP=stress NUM_ROBOTS=3`: 3 активных робота на P1-P3, P4-P5 — неактивны, в таблице, без управления.
- При `NUM_ROBOTS > количество_парковок`: количество активных не превышает парковок.
- Команда `go_home` без `target`: робот едет на свою парковку.
- Переключение `NUM_ROBOTS` не требует `python3 scripts/gen_world.py`.
- Переключение `MAP` работает без правок compose.
- В веб-интерфейсе неактивные роботы видны, но серые/без кнопок.

## 6. Риски
- `pyyaml` отсутствует в образе — добавить в Dockerfile.
- `colcon build` не обновит `install/` — пересобрать образ с `--build` или запустить `colcon build` вручную.
- Порядок парковок не предсказуем — сортировка по имени обязательна.
- Неактивный робот в SDF, но без драйвера — просто стоит на парковке, корректно.
- Мост стартует раньше `gz sim` — `TimerAction(period=5.0)`.
